# 千寻正式发布门槛

任何未通过项必须写明证据、原因、适用平台和负责人。版本号、源码、安装包、文档和校验值一致后才冻结；每次影响产品行为的修复都需相应回归。不得把构建、模拟测试、进程存活或旧窗口通过当作新版原生验收。

## Mac 原生验收

- [ ] 最终版本首次安装和重开无白屏；读取既有模型及登录配置，保留原资料。
- [ ] 手卡理解、AI 选项及手动调整、类目和达人条件保存往返一致；不自动开采。
- [ ] 精选联盟真实类目及内容类型提交回显，类目分页不回退关键词；证据不足待复核。
- [ ] 已有20人原生闭环证据与最终行为一致，逐项核对强身份、资料、作品、模型和明文联系人。
- [ ] 本批与往期划分正确；所有资料字段及修订记录显示并能重开保留；历史恢复不计新增。
- [ ] 当前批次界面、JSON、Excel、两个待发送队列及交接清单一致，无发送授权或实际外发。
- [ ] 各页面空状态、错误、忙碌、按钮防重复、搜索分页、详情和长文本布局通过真实界面核对。
- [ ] 原生完整备份成功；恢复到独立目录后资料、截图与交付引用可读，原数据不变，任务不自动运行，总数不重复。
- [ ] 损坏备份、错误路径、不可写目录和中断恢复有可见错误与恢复方式，不静默丢弃数据。

## 平台与发布包

- [ ] 完整回归、类型检查、前端构建通过并留存版本证据。
- [ ] Mac DMG/ZIP与安装版本一致，解包及签名状态明确，SHA256已生成。
- [ ] Windows NSIS/portable与冻结源码同版；内置Python和依赖哈希检查通过。
- [ ] 另一台 Mac 完成首次安装、登录保存、模型、原生小批采集、导出和恢复。
- [ ] Windows x64 完成内置运行环境烟测、软件首次安装、中文路径、登录、模型、采集暂停续跑、交付和备份恢复。
- [ ] 正式Apple签名公证和Windows发布者签名有真实证据；缺证书时明确标注。
- [ ] 文档不含旧菜单、旧路径、旧运行环境要求或虚假通过状态；客户包不含真实名单、联系人、密钥、会话和本地验收材料。
- [ ] GitHub指定仓库访问验证通过，审查清洁源码；发布同版安装包及SHA256并核对下载文件。

## 单独披露，不能推断通过

连续8小时与1000人目标；千问百炼真实调用；Jev官方账单；联系人实际可达性及平台展示差异；第三方建联实发。未做实际外发时，只能报告预览、导出和保护测试。
